# dotfiles

Личные dotfiles и bootstrap-скрипты для быстрого разворачивания окружения
на macOS и Linux (apt/dnf/pacman/zypper/apk): zsh + oh-my-zsh, tmux
(oh-my-tmux), neovim (AstroNvim), mc, alacritty, git, ssh, htop, eza,
pass/gnupg, rust, uv, docker.

## Структура

```
setup.sh          — установка пакетов, конфигов, seed/backup/restore
update.sh         — бэкап + синхронизация конфигов с системой + коммит/пуш
new-user.sh       — настройка уже созданного пользователя (в основном для macOS)
samba-share.sh    — быстрый расшаринг каталога по SMB (macOS/Linux)
config/           — сами dotfiles (git, mc, nvim, tmux, zsh, alacritty, ssh, htop)
lib/              — общие shell-хелперы (common.sh, packages.sh, deploy.sh, skel.sh)
PACKAGES.md       — подробный список пакетов, которые ставит setup.sh
```

## Быстрый старт

```bash
git clone <repo-url> ~/dotfiles
cd ~/dotfiles
./setup.sh
```

Скрипт определяет ОС и пакетный менеджер, ставит базовый набор пакетов,
раскладывает симлинки из `config/` в `$HOME`, делает zsh оболочкой по
умолчанию (`chsh`) и печатает, что осталось сделать руками (если что-то
не удалось поставить автоматически). После первого запуска перезапустите
терминал (или `exec zsh`), чтобы подхватить zsh/tmux.

Если `config/` пустой (свежий клон на новой машине, а настройки есть в
архиве с прошлой) — `setup.sh` предложит восстановление из бэкапа.

## Использование

### setup.sh

```bash
./setup.sh              # установить пакеты + разложить конфиги (+ restore при пустом config/)
./setup.sh seed         # собрать текущие настройки системы в config/ (обратное деплою)
./setup.sh backup [файл]            # упаковать config/ + ~/.ssh в tar.gz
./setup.sh restore <файл.tar.gz>    # восстановить config/ (и ~/.ssh) из архива
```

На Linux дополнительно публикует dotfiles в `/usr/local/share/dotfiles` и
раскладывает симлинки в `/etc/skel` — новые пользователи, созданные через
`useradd -m`, сразу получат эти конфиги. На macOS `/System/Library/User
Template` недоступен для записи (SIP), поэтому там для новых пользователей
нужен `new-user.sh`.

### update.sh

Бэкапит и синхронизирует конфиги с текущей системой (без переустановки
пакетов) — на случай, если приложение переписало файл поверх симлинка.

```bash
./update.sh            # бэкап + обновление config/ + локальный коммит
./update.sh --push      # то же самое, и сразу git push
./update.sh --no-backup # без архива-бэкапа (быстрее, но без сети безопасности)
```

### new-user.sh

Настраивает уже созданного пользователя: раскладывает конфиги и доклонирует
per-user зависимости (oh-my-zsh, oh-my-tmux, AstroNvim, тема alacritty).
Нужен только если пользователь создан ДО настройки `/etc/skel` (Linux) или
на macOS, где `/etc/skel`-аналог штатно недоступен.

```bash
sudo ./new-user.sh <имя_пользователя>
```

### samba-share.sh

Быстро поднимает общую сетевую папку (SMB/Samba) для каталога — на Linux
через пакет `samba` (секция в `smb.conf`, `smbd`/`nmbd`), на macOS через
штатную утилиту `sharing`.

```bash
./samba-share.sh [опции] <путь-к-папке>

  -n, --name ИМЯ        имя ресурса в сети (по умолчанию — имя каталога)
  -u, --user ЮЗЕР        кому дать доступ (по умолчанию — текущий пользователь)
  -p, --password ПАРОЛЬ  пароль Samba, ставится неинтерактивно (без TTY и без
                         этой опции создание пароля пропускается)
  -g, --guest            разрешить гостевой доступ без пароля
  -r, --readonly         общий доступ только на чтение
  -h, --help              эта справка
```

На macOS тумблер "File Sharing" в System Settings и первичное подтверждение
пароля Apple не даёт включить из терминала — скрипт выведет точную
подсказку, что доделать руками.

## Требования

- bash, git
- sudo (или запуск от root) для шагов, требующих привилегий — на системах
  без sudo и не под root часть шагов помечается как "сделать вручную"
